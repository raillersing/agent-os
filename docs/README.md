# Agent OS Controlled Documentation

The documentation is organized by responsibility rather than by implementation technology.

| Directory | Purpose |
|---|---|
| `00-governance` | Documentation control, glossary, roles, standards, ADRs |
| `01-product` | Vision, scope, PRD, personas, value and roadmap |
| `02-requirements` | Functional, non-functional and traceability specifications |
| `03-architecture` | System, domain, data, memory, integration and deployment architecture |
| `04-contracts` | OpenAPI, AsyncAPI, schemas and interoperability profiles |
| `05-ai-governance` | Autonomy, routing, prompts, evaluation, memory and AI cost policy |
| `06-security` | IAM, threat model, sandboxing, secrets, privacy and incident response |
| `07-ux-design` | Information architecture, design system, accessibility and validation |
| `08-delivery` | Development, testing, quality gates, release and migration |
| `09-operations` | DevOps, observability, SLOs, backup, scaling and runbooks |
| `10-modules` | Functional module specifications |
| `11-integrations` | Agent, provider, tool and business-system adapter specifications |
| `12-user-documentation` | Tutorials, how-to guides, reference and explanations |
| `13-assurance` | Acceptance, security, performance, accessibility and release evidence |

The authoritative register is `document-register.yaml`.
